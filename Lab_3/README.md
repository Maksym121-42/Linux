# Завдання 1                       
Після запуску Docker-контейнера було досліджено обмеження на кількість відкритих файлів за допомогою команди ulimit.                           

**На початку було отримано такі значення:**
ulimit -n → 1048576           
soft limit → 1048576       
hard limit → 1048576   

**Після виконання команди:**
ulimit -n 3000 

**було встановлено нове значення обмеження:**        
soft limit → 3000            
hard limit → 3000         

**Далі була виконана спроба збільшити ліміт:**    
ulimit -n 3001     

**У результаті отримано помилку:**       
bash: ulimit: open files: cannot modify limit: Operation not permitted      

Це означає, що значення обмеження не може перевищувати допустимий максимум.  

**Після цього ліміт було зменшено:**       
ulimit -n 2000             

**Отримані значення:**         
soft limit → 2000          
hard limit → 2000              

**Повторна спроба збільшити значення до 3000:**            
ulimit -n 3000            
      
**знову призвела до помилки:**          
Operation not permitted

У даній роботі за допомогою програми Lab3_6 ( з попереднього, 6 завдання ) було досліджено вплив обмеження розміру стеку (ulimit -s) на глибину рекурсії.

Програма використовує рекурсивні виклики функції, при яких кожен новий виклик займає додаткову пам’ять у стеку. Це дозволяє наочно спостерігати момент переповнення стеку.

Було встановлено різні значення розміру стеку та запущено програму:   

При обмеженні *ulimit -s 32*              
програма досягла глибини рекурсії приблизно 5 викликів, після чого завершилась з помилкою:            
*Segmentation fault (core dumped)*           

При обмеженні *ulimit -s 64*               
програма досягла глибини рекурсії приблизно 14 викликів, після чого також завершилась з помилкою:
